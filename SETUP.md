# Setup, configuration, deployment and release

Canonical guide for running, testing, configuring, deploying and releasing Bharat Map. It merges the former
`docs/CONFIGURATION.md` and `docs/DEPLOYMENT.md` (both now pointers). Deep references kept in `docs/`:
[docs/SELF_HOSTING.md](docs/SELF_HOSTING.md) (self-hosted Valhalla / Photon / Nominatim / OSRM),
[docs/ANDROID.md](docs/ANDROID.md) (native capabilities, permissions, install), [docs/OFFLINE_ROUTING.md](docs/OFFLINE_ROUTING.md)
(Valhalla graph build). Secrets are documented **by name and purpose only**; never put a value in a doc or commit.

## Requirements

| Need | Version / note |
|---|---|
| Node.js | ≥ 22.13 (`package.json` `engines`; uses built-in `node:sqlite`, no native builds). CI uses Node 22 |
| npm | `npm ci` (lockfile committed) |
| Browser E2E | Chromium at `/usr/bin/chromium` or `$CHROME`, plus Noto fonts (Debian/Ubuntu: `chromium`, `fonts-noto-core`) for Indic glyphs; `playwright-core` is a devDependency (no bundled browser) |
| Android build | JDK 21 + Android SDK 35 on x86_64 (CI does this). **Not possible in the aarch64 sandbox** — APKs are built only by CI |

## Run locally

```bash
npm ci
npm run migrate          # creates data/mapos.db, applies db/migrations/*, seeds fictional demo data
npm start                # http://localhost:8080  (npm run dev = node --watch)
```

Background server for E2E/dev: `scripts/dev-restart.sh` (kills the PID in `data/server.pid`, starts
`PORT=8080 LOG_REQUESTS=0 node server/index.js` with output in `data/server.log`, then curls `/api/health`).

Demo logins (development only): `customer@mapos.demo`, `seller+b2@mapos.demo`, `admin@mapos.demo`, password `demo1234`
(override with `DEMO_PASSWORD`). In production there is no known password: `ADMIN_PASSWORD` (≥ 12 chars) is required and
demo accounts get `DEMO_PASSWORD` (≥ 12 chars) or a random password (`server/db.js#demoPasswordFor`).

Serverless demo: `npm run build:demo` → `dist/india-mapos-demo.html` (one file; MapLibre from a CDN unless
`LOCAL_VENDOR=1`). This tracked file is regenerated by the build — **do not stage it** in commits.

authoritative. E2E writes `docs/e2e-results.txt`, screenshots and (full runs) `docs/perf-v04.json` — **never stage
`docs/perf-v04.json` or regenerated v03–v06 / v0718 screenshots**; `docs/screenshots/v0718/e2e-*.png` is gitignored.

## Debug

| Symptom | Where to look |
|---|---|
| Server errors | JSON logs on stdout (`LOG_REQUESTS=1`); 500s include `request_id` matching the `X-Request-Id` header; `data/server.log` when started by `dev-restart.sh` |
| Upstream (routing/geocode) failures | `GET /api/v1/providers` (breaker state, counters); responses carry `provider`, `engine`, `tried[]`, `fallback` |
| Which integrations are on | `GET /api/config`, `GET /api/payments/config`, `GET /api/v1/integrations`, `GET /api/v1/traffic/status` |
| Health / metrics | `GET /api/health`, `GET /metrics` (token or non-production) |
| Map not drawing | In-app map-failure banner (`web/ui/map-health.js`); headless Chromium has no internet — use fixtures or the `/map` tile proxy |
| One E2E step | `ONLY='v0720 desktop' node tests/e2e.mjs` |
| Search index | `GET /api/v1/places/search?q=…` (`engine: fts5` or `token-index`) |

### Payments (`server/payments/index.js`)

Each gateway is enabled only when all its keys are present. With none: `/api/payments/config` → `configured: false`,
`POST /api/payments/orders` → `503 payments_not_configured`, the payment screen says "Payments not configured" and the
order stays `pending_payment`. Cashfree, PhonePe and Paytm are **prototype adapters** never run against a live sandbox.

| Variable | Gateway / purpose |
|---|---|
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_API_BASE` | Razorpay (functional, test mode); webhook URL `https://<host>/api/payments/razorpay/webhook`; API base override for tests |
| `CASHFREE_APP_ID`, `CASHFREE_SECRET_KEY`, `CASHFREE_ENV`, `CASHFREE_API_BASE` | Cashfree (prototype); `CASHFREE_ENV=production` = live API, else sandbox |
| `PHONEPE_CLIENT_ID`, `PHONEPE_CLIENT_SECRET`, `PHONEPE_CLIENT_VERSION`, `PHONEPE_ENV`, `PHONEPE_AUTH_BASE`, `PHONEPE_PG_BASE`, `PHONEPE_WEBHOOK_USER`, `PHONEPE_WEBHOOK_PASSWORD` | PhonePe PG v2 (prototype) |
| `PAYTM_MID`, `PAYTM_MERCHANT_KEY`, `PAYTM_WEBSITE`, `PAYTM_ENV`, `PAYTM_API_BASE` | Paytm PG (prototype); website default `WEBSTAGING` / `DEFAULT` |

## Deployment

### Option A — single container
```bash
cp .env.example .env     # set JWT_SECRET, ADMIN_PASSWORD, CORS_ORIGINS, HTTP_USER_AGENT, DEMO_PASSWORD (≥ 12) …
docker build -t bharat-map .
docker run -d --name bharat-map -p 8080:8080 --env-file .env -v mapos-data:/data --restart unless-stopped bharat-map
curl localhost:8080/api/health
```
The `Dockerfile` (node:22-bookworm-slim, `npm ci --omit=dev`, runs as `node`, `HEALTHCHECK` on `/api/health`) sets
`NODE_ENV=production`, `PORT=8080`, `DB_FILE=/data/mapos.db` and replaces the `web/shared` symlink with a copy. Put a
TLS reverse proxy in front with streaming enabled for SSE (Caddy: `reverse_proxy localhost:8080 { flush_interval -1 }`),
set `TRUST_PROXY=1`, back up `/data/mapos.db` with `sqlite3 … ".backup …"`. India-hosted regions are recommended for
latency and the DPDP posture.

### Option B — docker compose with self-hosted services
`docker-compose.yml` services and profiles (verified): `app` (no profile), `valhalla` (profile `routing`), `photon` and
`nominatim` (profile `geocoding`), `osrm` (profile `osrm`), `postgis` (profile `next`, not used by the code yet). Example:
`docker compose --profile routing --profile geocoding up -d`. Build the OSRM graph first with `scripts/prepare-osrm.sh`.
Details and sizing: [docs/SELF_HOSTING.md](docs/SELF_HOSTING.md). (The former DEPLOYMENT text named profiles that do not
match the compose file; this section follows the file.)

### Option C — Render (planned, not done)
`render.yaml` defines a Docker web service `india-mapos-api` (free plan, Singapore, health `/api/health`,
`JWT_SECRET` generated, `ADMIN_PASSWORD` and payment keys entered in the dashboard, `CLIENT_SERVICES=server`).
Steps once the owner has a Render account: New → Blueprint → this repo → set `ADMIN_PASSWORD` (≥ 12) and optional
Razorpay test keys → then add the GitHub **repository variable** `MAPOS_API_BASE=https://<service>.onrender.com` so the
next APK uses it. Free-plan caveats: sleeps after idle, no persistent disk (SQLite resets on redeploy). The CSP still
allows `*.onrender.com` until the final host is known (audit AUD-26). **Status: not deployed** (needs the owner's account).

### Scaling (target, not built)
More than one API replica requires PostgreSQL/PostGIS (`db/postgis/`) and Redis for rate limits, login lockout, tile
cache and SSE fan-out; tiles from a planetiler/PMTiles build with Survey-of-India boundaries on object storage + CDN;
self-hosted Valhalla/OSRM/Photon/Nominatim. Public demo servers must not carry production traffic.

## Android release and signing

**Versioning.** CI sets `VERSION_NAME=0.7.<run_number>` and `VERSION_CODE=<run_number>`; the GitHub release tag is
`v0.7.<run>`. `package.json` (`0.7.0`) and `server/app.js` `VERSION` (`0.7.0`) are not bumped per release.

**What CI does on every push to `main`** (`.github/workflows/ci.yml`): `test` (npm ci, `npm test`, `npm audit
--audit-level=high`, secret-pattern scan) → `e2e` (server on :8080 + `tests/e2e.mjs`) and `android` (build `www/`,
`cap sync`, `assembleDebug assembleRelease`, lint non-blocking) → **publishes release `v0.7.<run>`** with the debug APK
(and the release APK only when signing secrets exist). Commits whose message contains `[skip ci]` do not run CI (GitHub
built-in behaviour) — use it for docs-only commits. Actions are SHA-pinned; only the android job has `contents: write`.

**Release key.** PKCS12, alias `bharatmap`, RSA 4096, `CN=Bharat Map`, created 19 Oct 2026, valid 10,000 days.
Certificate SHA-256 `d04d20f9fd727d7ca6d966e771e2ed5760b20fefe9c139d36f0e3e86b7997c6c` (pinned in `ci.yml` and
`attach-apk.yml`). The keystore and its passwords live **outside the repo** in the project-root `signing/` folder
(gitignored, as are `*.jks`, `*.keystore`). Never print, copy into the repo, or commit its contents or passwords. Losing
it means no future build can update installed copies.

**CI secrets (not set yet — owner action).** Settings → Secrets and variables → Actions → Repository secrets:
`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. The automation's GitHub token
cannot write Actions secrets, so the owner must add them in the GitHub UI. Until then CI uploads
`bharat-map-0.7.<run>-release-unsigned.apk` as a 7-day artifact (`bharat-map-release-unsigned`) and publishes only the
debug APK.

**Offline signing procedure (current practice).**
1. Download the unsigned artifact of the CI run.
2. Work in `/tmp` (apksigner has segfaulted on some sandbox filesystems — operational note from earlier releases).
3. `zipalign -P 16 4 in.apk aligned.apk`, then `apksigner sign --ks <signing/…jks> --ks-key-alias bharatmap
   --ks-pass env:<VAR> --key-pass env:<VAR> --out bharat-map-0.7.<run>.apk aligned.apk` (passwords from the environment,
   never on the command line or in logs), then `apksigner verify --print-certs` (cert SHA-256 must match) and
   `zipalign -c -P 16 4`.
4. Publish the APK at a short-lived URL and run the manual workflow `.github/workflows/attach-apk.yml` with inputs
   `url`, `sha256`, `tag` (e.g. `v0.7.20`), `name` (`bharat-map-0.7.20.apk`). It re-checks the hash, signature, pinned
   certificate, alignment and that the APK is not debuggable, then `gh release upload --clobber`.
   Dispatch it through the REST endpoint `POST /repos/Hem456anth/BharatMap/actions/workflows/attach-apk.yml/dispatches`
   with a JSON body `{"ref":"main","inputs":{…}}` — the `apicall github workflow_dispatch` wrapper dropped `inputs`
   (HTTP 422) during the 0.7.20 release.

**Build type.** Release builds are not debuggable and have **no R8/minification and no resource shrinking**
(`minifyEnabled false`, `shrinkResources false`). APK ≈ 100 MB (v0.7.20: 100,688,504 bytes); the 11 bundled city PMTiles
are 81,396,970 bytes. Slimming is **not approved** — see [DECISIONS.md](DECISIONS.md) ADR-012.

**Upgrading old installs.** 0.5.12 and older were debug-signed; uninstall once, then release builds (0.5.13+) update
in place. Install steps for phones: [docs/ANDROID.md](docs/ANDROID.md#install-the-apk).
